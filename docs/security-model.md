# 安全模型与限制

## 设计保证

- `Finding` 不保存命中内容，只包含类型、置信度和半开 UTF-16 区间。
- 默认脱敏标记不包含原值；批量摘要只有分类计数。
- 同一输入和策略产生确定性结果，不使用随机数或网络服务。
- 重叠检测先排序再合并，避免二次替换破坏偏移。
- 已脱敏标记可再次处理，不会把 marker 当作新的 credential（0.2.0 起 Bearer 检测同样
  跳过 marker，`PreserveLast4` 重复处理也保持幂等）。
- `redact_json` 的输出是键按字典序排列的紧凑 JSON（RFC 8785 风格成员排序），同一输入
  总是产生字节级一致的输出；findings 以 JSON 指针风格 path 标注位置，不含字段值。

## 威胁边界

库处理调用方已提供的字符串，不读取文件、剪贴板、环境变量或网络。原始字符串在调用方
内存中仍然存在；本库不能擦除语言运行时的旧副本。检测规则不是穷举，编码、混淆、分块
或未知格式的秘密可能漏检。邮箱与 IP 也可能是测试数据，属于可能误报。

支付卡检测做字符收集、Luhn 校验和主流卡组织 BIN 前缀判断（Visa 4、Mastercard 5、
Discover/UnionPay 6、Amex 34/37），不判断有效期或持卡人，也不构成 PCI 合规。默认情
况下 Luhn 有效但 BIN 之外的数字串按订单号抑制；关闭 `require_known_card_prefix` 可
恢复全量候选。IPv4 检测默认抑制粘在更长 token 上的版本形态（`v1.2.3.4`、
`2.0.0.1rc1`）；关闭 `suppress_version_ipv4` 可恢复。两类抑制都是精确率优先的取舍，
高召回场景应显式关闭并自行处理误报。`PreserveLast4` 明确泄露四个末尾字符，只应用于
允许保留部分形状的调试场景。

## 流式与 JSON 的附加边界

`ChunkScanner` 只保证完整跨度不超过 `overlap` 的秘密不因分块而漏检：跨块秘密的前段
必须仍落在保留窗口内。PEM 私钥块可能超过默认 8192 码元窗口，处理这类输入时应显式调
大 `overlap`。findings 的偏移是整个流的绝对 UTF-16 偏移，调用方映射回原文时需注意两
者基于同一码元口径。

`redact_json` 解析后的数字以 IEEE 754 Double 规范化输出（`1e3` 变为 `1000`，
`5432.50` 变为 `5432.5`），超出 2^53 的整数可能失去精度。输入不是合法 JSON 时走
fail-closed 路径：按纯文本扫描并置 `parsed=false`；调用方应将该标志视为降级信号。

## 推荐接入

在日志写入、外部 API 发送或 AI 请求提交之前调用 `redact`；高敏感路径采用 `Typed` 或
`Marker`，随后调用 `verify_clean`。若验证失败，应拒绝发送并记录类别统计，不要记录原文。
流式日志使用 `ChunkScanner` 时，`overlap` 取工程上最长秘密的跨度上界；JSON 接口响应
直接使用 `redact_json`，对 `parsed=false` 的响应按处理失败对待。
