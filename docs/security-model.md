# 安全模型与限制

## 设计保证

- `Finding` 不保存命中内容，只包含类型、置信度和半开 UTF-16 区间。
- 默认脱敏标记不包含原值；批量摘要只有分类计数。
- 同一输入和策略产生确定性结果，不使用随机数或网络服务。
- 重叠检测先排序再合并，避免二次替换破坏偏移。
- 已脱敏标记可再次处理，不会把 marker 当作新的 credential。

## 威胁边界

库处理调用方已提供的字符串，不读取文件、剪贴板、环境变量或网络。原始字符串在调用方
内存中仍然存在；本库不能擦除语言运行时的旧副本。检测规则不是穷举，编码、混淆、分块
或未知格式的秘密可能漏检。邮箱与 IP 也可能是测试数据，属于可能误报。

支付卡检测只做字符收集和 Luhn 校验，不判断发卡机构、有效期或持卡人，也不构成 PCI
合规。`PreserveLast4` 明确泄露四个末尾字符，只应用于允许保留部分形状的调试场景。

## 推荐接入

在日志写入、外部 API 发送或 AI 请求提交之前调用 `redact`；高敏感路径采用 `Typed` 或
`Marker`，随后调用 `verify_clean`。若验证失败，应拒绝发送并记录类别统计，不要记录原文。
